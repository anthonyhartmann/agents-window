Plan: Adapt Agent Chat UI for Cline

Goal

Replace your custom agent/window interface with the polished LangChain Agent Chat UI, wired directly to Cline as the backend agent engine. The result is a Next.js web app that looks like agent-chat-ui but talks to Cline's SDK instead of LangGraph.

What We Learned

Agent Chat UI Architecture

  • Next.js 15 app using React 19, Tailwind, shadcn/ui
  • Streams messages via @langchain/langgraph-sdk/react useStream
  • Expects a LangGraph-compatible HTTP API with /threads, /runs endpoints
  • Renders human messages, AI messages, tool calls, generic interrupts, and artifacts
  • Has a setup form for Deployment URL, Assistant ID, and API key

Cline SDK Architecture (locally available)

  • @cline/sdk v0.0.65 is bundled inside your globally installed cline package at: ~/.asdf/installs/nodejs/22.22.1/lib/node_modules/cline/node_modules/@cline/...
  • Key classes: ClineCore (session host), Agent (stateless loop)
  • Session API:
    • ClineCore.create({ clientName: "..." }) → initializes runtime
    • cline.start({ config: { provider, model, workspaceRoot }, prompt }) → starts session
    • cline.send(sessionId, { prompt, userImages, userFiles }) → sends follow-up
    • runtimeHost.subscribe((event: CoreSessionEvent) => ...) → streams events
  • Events: chunk (stdout/stderr/agent), agent_event (content_start, content_update, content_end, iteration_start, iteration_end, usage, done, error), ended, hook, status
  • Persistence: Sessions saved to ~/.cline/data/db/sessions.db and ~/.cline/data/sessions/<id>/
  • Tool calls: Built-in tools (bash, editor, read_files, search, fetch_web) + MCP servers

Implementation Phases

Phase 1: Project Bootstrap (1-2 hours)

  1. Clone github.com/langchain-ai/agent-chat-ui into a new directory (e.g., ~/Projects/cline-chat-ui or ~/.cline/cline-chat-ui)
  2. Switch Node version to 22.22.1 (where cline and @cline/sdk are installed) or copy the @cline/* scoped packages into the project
  3. Install dependencies: pnpm install
  4. Add local SDK dependency: link or copy @cline/sdk, @cline/core, @cline/shared, @cline/agents, @cline/llms from the global cline package into the project's node_modules or package.json
  5. Verify build: pnpm dev should still start the vanilla agent-chat-ui

Phase 2: Backend API Routes (2-3 hours)

  1. Remove the LangGraph API proxy route (src/app/api/[..._path]/route.ts)
  2. Create /api/chat/stream/route.ts — Server-Sent Events (SSE) endpoint:
    • POST request body: { threadId?: string, messages: Array<{ role: "user" | "assistant", content: string }> }
    • If threadId missing → const result = await clineCore.start({ config: { provider, model, workspaceRoot, enableTools: true }, prompt: lastUserMessage })
    • If threadId present → await clineCore.send(threadId, { prompt: lastUserMessage })
    • Subscribe to events: runtimeHost.subscribe((event) => { write SSE data })
    • Map events to a simple JSON stream protocol the frontend understands:
      • { type: "text_delta", text: "..." }
      • { type: "tool_call", name: "...", input: {...} }
      • { type: "tool_result", name: "...", output: {...}, error?: "..." }
      • { type: "usage", inputTokens: N, outputTokens: N }
      • { type: "done" }
      • { type: "error", message: "..." }
  3. Create /api/threads/route.ts — GET list of threads:
    • Query Cline's SqliteSessionStore or read ~/.cline/data/db/sessions.db
    • Return threads in format: { threads: [{ thread_id, created_at, updated_at, metadata: { name } }] }
  4. Create /api/threads/[id]/route.ts — GET thread messages:
    • Read ~/.cline/data/sessions/<id>/<id>.messages.json
    • Parse and map to frontend message format

Phase 3: Custom Stream Provider (2-3 hours)

  1. Replace src/providers/Stream.tsx:
    • Remove imports from @langchain/langgraph-sdk/react
    • Remove the setup form (LangGraph URL, assistant ID, API key)
    • Create useClineStream() hook with interface matching agent-chat-ui's expectations:
      • messages: Message[]
      • isLoading: boolean
      • submit({ messages }, options) — opens SSE to /api/chat/stream, appends user message optimistically, processes streamed events into AI message
      • stop() — aborts the SSE connection
      • getMessagesMetadata(message) — returns branch info (simplified)
    • Keep threadId in query state (nuqs)
  2. Handle SSE parsing in the hook:
    • EventSource or fetch + ReadableStream reader
    • Parse each JSON line and mutate local message state
    • Append text deltas to the current AI message
    • Inject tool call / tool result messages when events arrive

Phase 4: Message Format Adapter (1-2 hours)

  1. Define shared types in src/lib/cline-types.ts:
    • ClineStreamEvent = TextDeltaEvent | ToolCallEvent | ToolResultEvent | UsageEvent | DoneEvent | ErrorEvent
    • ClineMessage = { id: string, type: "human" | "ai" | "tool", content: string | ContentBlock[], tool_calls?: ToolCall[], ... }
  2. Map Cline AgentEvents to UI messages:
    • agent_event → content_start / content_update / content_end:
      • contentType: "text" → append to AI message text
      • contentType: "tool" with toolName / input → create ToolCalls message
      • contentType: "tool" with output / error → create ToolResult message
    • chunk with stream: "agent" → treat as text output
    • done / ended → finalize streaming state
  3. Adapt src/components/thread/messages/ai.tsx and human.tsx:
    • Keep rendering logic mostly intact
    • Update type imports to use local ClineMessage instead of @langchain/langgraph-sdk/Message
    • ToolCalls and ToolResult components likely need minimal changes

Phase 5: Thread History & Persistence (1-2 hours)

  1. Update src/providers/Thread.tsx:
    • Remove LangGraph client creation
    • Implement getThreads() by calling /api/threads
    • Format dates and metadata from Cline session records
  2. Add auto-refresh when new messages arrive:
    • After submit() completes, refetch thread list (same pattern as original)
  3. Handle empty states and loading skeletons

Phase 6: UI Polish & Config (1-2 hours)

  1. Simplify the top bar:
    • Remove LangGraph logo
    • Add Cline branding or keep it neutral
    • Show current model/provider (read from Cline settings)
  2. Add provider/model selector (optional):
    • Dropdown to switch between Cline-configured providers
    • Read available providers from ~/.cline/data/settings/providers.json
  3. Keep existing features:
    • File upload (images, PDFs) → pass through to Cline via userImages / userFiles
    • "Hide Tool Calls" toggle
    • Scroll-to-bottom behavior (use-stick-to-bottom)
    • Artifact panel for generated files
  4. Theme/dark mode: already works via next-themes

Phase 7: Testing & Validation (1 hour)

  1. Start the dev server: pnpm dev
  2. Send a test message → verify Cline session starts in ~/.cline/data/sessions/
  3. Verify streaming text appears in real-time
  4. Verify tool calls render correctly
  5. Verify thread history loads on refresh

Risks & Mitigations

| Risk | Mitigation | |------|------------| | @cline/sdk is not on npm | Use the bundled copy inside the global cline package (Node 22.22.1) | | Cline SDK requires Node ≥22 | Ensure the project runs on Node 22.22.1 or install SDK under the active Node version | | Cline hub daemon port conflict (25463) | The SDK will auto-connect to the existing hub; our API routes run in the same machine | | Session format changes in future Cline versions | Pin to current SDK version; adapter layer isolates changes | | SSE streaming complexity | Start with simple fetch + ReadableStream; upgrade to EventSource if needed | | Tool call rendering mismatch | Map Cline events to LangGraph-style tool_calls / tool messages for reuse of existing UI |

One Decision Needed From You

Should the chat UI share sessions with your existing Cline CLI / VS Code usage?

Option A: Shared Sessions (Recommended)

  • ClineCore.create({ clientName: "cline-chat-ui" }) uses the default ~/.cline/data/ directory
  • Threads you start in the web UI show up in Cline CLI / VS Code
  • Existing Cline sessions appear in the web UI thread list
  • Tradeoff: The UI must handle session types it didn't create (e.g., coding tasks with file edits)

Option B: Isolated Sessions

  • Configure ClineCore.create({ clientName: "cline-chat-ui", dataDir: "~/.cline-chat-ui/data" }) (if supported) or maintain a separate thread list
  • Web UI only shows its own conversations
  • Tradeoff: No cross-client history; simpler mapping

Option C: Read-only shared history, isolated new chats

  • List all Cline sessions in sidebar, but only open new chat sessions through the web UI
  • Tradeoff: Best of both worlds, but opening existing coding sessions in a chat UI may be weird

Please let me know which option you prefer, or if you want to start with Option A and iterate.
